System Architecture

Factory Inventory Management System

A full-stack demo application for tracking inventory, orders, demand forecasting, backlog, and spending across factory warehouses. Single-page Vue 3 frontend backed by a Python FastAPI service over in-memory mock data.

Vue 3 SPA · port 3000 FastAPI · port 8001 In-memory JSON data No database

Overview

System Architecture

Three logical tiers. The browser runs the Vue SPA, which talks to FastAPI over HTTP/JSON; FastAPI filters and validates data held entirely in memory.

Client Tier — Browser (Vue 3 SPA, Vite dev server :3000)
Views & Router
6 routed pages: Dashboard, Inventory, Orders, Demand, Spending, Reports (vue-router)
Components & Composables
FilterBar, detail modals, ProfileMenu; useFilters / useAuth / useI18n shared state
API Client — api.js
Axios wrapper; builds query params from active filters
HTTP · JSON · Axios ⇅ requests with filter query params / typed JSON responses
Application Tier — FastAPI + Uvicorn (:8001)
Routes — main.py
14 GET endpoints across inventory, orders, dashboard, demand, backlog, spending, reports
Filtering Logic
apply_filters() + filter_by_month() — warehouse, category, status, month/quarter
Pydantic Models
Request/response validation & typed schemas (response_model)
CORS: all origins allowed (development only) so the :3000 dev server can call :8001 directly.
in-process function calls ⇅ load once at startup / filter on each request
Data Tier — In-Memory (loaded from JSON at startup)
Loader — mock_data.py
Reads all JSON files into module-level Python lists/dicts on import
server/data/*.json
inventory, orders, demand_forecasts, backlog_items, spending, transactions, purchase_orders
No Database
State lives in memory; changes do not persist — a restart reloads from the JSON files

Reactivity model: raw responses are stored in ref()s (e.g. allOrders, inventoryItems); all derived values — totals, low-stock counts, chart series — are computed() properties that recompute only when their dependencies change.
Shared filters: four filters — Time Period, Warehouse, Category, Order Status — live in a composable and apply across every data view via query parameters.
